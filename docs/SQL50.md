# SQL 50 题库说明

本版本新增独立「SQL 50」题单，通过左侧按钮与「热题 100」切换。两个题单分别统计进度，每题草稿、笔记、收藏、提交及聊天使用不同题目 ID。SQL 编号内部使用 sql- 前缀，界面仍显示力扣原题号。原 Hot 100 的题面、测试数据、Python/C++ 模板与算法运行器未修改。

题单依据 [力扣官方 SQL 50](https://leetcode.com/studyplan/top-sql-50/) 于 2026-09-12 获取的 50 题和 7 个分组。全部中文正文为项目基于官方英文原文编写的译文，界面明确标注「中文译文」。原文和官方示例缓存于 data/sql-official-cache，生成脚本为 scripts/sql-build-catalog.py。

## 练习方式

选择 SQL 50 → 阅读中文题意与表结构 → 编写单条 SQL → 点击「运行 SQL」查看预期/实际表格 → 提交给 GPT 批改 → 在右侧继续追问 → 自行标记完成。回到 Hot 100 会恢复此前题目和编程语言。

运行环境为软件附带 Python sqlite3 提供的 SQLite 3.50.4，不需要安装数据库服务，不连接学习记录数据库。每个用例都创建新的内存库，自动建表并插入固定测试数据。查询题允许 SELECT/WITH；第 196 题允许 DELETE 并比较 Person 剩余记录。删除不会改变后续用例或用户存档。

输出按列名（忽略大小写）、单元格类型与值、重复次数比较。NULL 与字符串不同，数字采用相对误差 1e-6。题目要求顺序时检查顺序；620 题允许相同评分行交换先后。结果表保留空结果列名，界面标识 NULL 与空字符串。最多返回 1000 行 / 128 KiB，界面表格预览前 200 行并标明总数。每例 3 秒、256 MiB，支持停止。

## SQLite 与力扣方言

这里验证的是 SQLite 本地结果。力扣 MySQL、PostgreSQL 等方言及官方隐藏用例没有在本软件执行，不提供自动提交或官方 AC 同步。

- 日期用 TEXT 的 ISO 格式保存。可使用 date、julianday、strftime；MySQL 的 DATE_FORMAT 和 DATEDIFF 不可直接使用。
- 比例计算注意整数除法，例如乘以 1.0 或 100.0。
- 字符串可用 substr、upper、lower、||、group_concat；参数及聚合排序语法需按 SQLite 调整。
- SQLite 不内建 REGEXP。1517 题可用 GLOB 组合字符集合约束；GLOB 区分大小写，LIKE 默认对 ASCII 不区分大小写。
- 196 题使用 SQLite DELETE FROM Person 语法，不使用 MySQL 多表 DELETE。
- SQL 暂不提供自动格式化；原 Python/C++ 格式化功能保留。

参考 [SQLite SELECT](https://www.sqlite.org/lang_select.html)、[日期函数](https://www.sqlite.org/lang_datefunc.html)、[核心函数](https://www.sqlite.org/lang_corefunc.html)。

## 实际数据校验

50 题参考 SQL 已由实际 SqlRunner 执行：103/103 个用例通过，包括 53 个公开示例（其中一例有下述笔误修正）及 50 个独立编写边界用例。额外验证 5 种代表错解确实未通过。参考实现放在 scripts/sql-reference-solutions.json，供核验和学习使用，初始编辑器不显示答案。

运行方式：Node.js 22.12+ 下执行 node --test tests/sql-catalog.test.cjs tests/sql-runner.test.cjs tests/sql-service.test.cjs tests/store.test.cjs。桌面验证：先构建，再执行 node tests/sql-desktop.cjs。实际 AI 检查使用 --live，显式使用已有 ChatGPT 凭据所在的官方目录，学习档案独立，原始对话证据不纳入公开源码。

公开说明中的修正与差异：

- 1731 题第二个官方结果表含使用竖线的横向分隔行。生成器过滤该分隔行，避免将其当成数据。
- 1484 题官方输入商品为 T-Shirt，输出写为 T-shirt。项目保留输入，修正预期输出为 T-Shirt，并在该题提示及用例来源中标注。原始缓存不修改。
- 180 题正文示意将 num 标为 varchar，官方数据库元数据使用 INT。本地遵循该元数据使用 INTEGER，并在中文约束说明。
- 日期、ENUM、VARCHAR 以 TEXT 存储；声明的唯一键、外键和枚举语义写在题面。测试库没有建索引，不将参考查询运行时间解释为实际生产数据库性能。

这些是公开示例和项目边界测试，不能证明隐藏测试全部通过。
